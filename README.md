# eks-argo-bootstrap

Public ArgoCD bootstrap repo for EKS clusters provisioned by `eks-pulumi`. No AWS-account-specific data lives in this repo — clusters supply config via the in-cluster Secret's annotations, and ApplicationSets read those at sync time via `{{metadata.annotations.X}}`.

## Contract with `eks-pulumi`

`eks-pulumi` provisions an in-cluster Secret labeled `argocd.argoproj.io/secret-type=cluster` with these 14 annotations:

| Annotation | Provider | Used by |
|---|---|---|
| `aws_account_id` | account context | (general) |
| `aws_region` | account context | karpenter, ALB, fluent-bit |
| `cluster_name` | cluster identity | karpenter, ALB |
| `vpc_id` | network identity | aws-load-balancer-controller (explicit; avoids IMDS auto-detect under hop-limit=1) |
| `karpenter_role_arn` | IRSA | karpenter controller SA |
| `karpenter_node_role_name` | EC2 role | karpenter NodePool |
| `karpenter_interruption_queue_name` | SQS | karpenter |
| `alb_role_arn` | IRSA | aws-load-balancer-controller SA |
| `ebs_csi_role_arn` | IRSA | aws-ebs-csi-driver SA |
| `efs_csi_role_arn` | IRSA | aws-efs-csi-driver SA |
| `external_secrets_role_arn` | IRSA | external-secrets SA |
| `fluentbit_role_arn` | IRSA | fluent-bit SA |
| `oidc_provider_arn` | IRSA trust | (general) |
| `oidc_provider_url` | IRSA trust | (general) |

ApplicationSets read these via `{{metadata.annotations.X}}` and substitute them into Helm `valuesObject` blocks at sync time. **Never** hardcode account-specific values in this repo.

## ApplicationSet shape

Every chart in this repo is delivered via one canonical ApplicationSet shape (see `bootstrap/applicationsets/cert-manager.yaml` for the reference). Required elements:

1. `kind: ApplicationSet` in namespace `argocd`.
2. `spec.syncPolicy.preserveResourcesOnDeletion: true`.
3. Cluster generator with selector `argocd.argoproj.io/secret-type=cluster` (matches every registered remote cluster).
4. `template.metadata.annotations.argocd.argoproj.io/sync-wave: "<wave>"` — see `docs/sync-waves.md`.
5. Two-source pattern: `ref: values` source pointing at this repo (`https://github.com/slikk66/eks-argo-bootstrap`) + Helm chart source.
6. Helm `releaseName: <chart>` set explicitly (default would derive from Application name and break service discovery).
7. `valueFiles: [$values/charts/<chart>/values.yaml]` for static config.
8. `valuesObject` for annotation-templated dynamic config (IRSA role ARNs, cluster name, region, vpc id) — empty for cert-manager since it consumes none of the 14.
9. `destination.name: '{{name}}'`, `destination.namespace: <chart-namespace>`.
10. `syncPolicy.automated: { prune: true, selfHeal: true }` and `syncOptions: [CreateNamespace=true, ServerSideApply=true]`.
11. Helm chart `targetRevision` MUST be a pinned version (`v1.20.2`, NOT `*` / `HEAD` / blank).

## Sync wave convention

| Wave | Chart | Why |
|---|---|---|
| -10 | cert-manager | webhooks for ALB & others depend on it |
| -5  | karpenter (controller + CRDs) | data plane needs Karpenter alive before nodes |
| 0   | ALB, ESO, EBS/EFS CSI, metrics-server, ADOT, fluent-bit, argocd-self | parallel addons |
| 5   | karpenter NodePool + EC2NodeClass | depends on karpenter controller running |

**Honest caveat:** sync-wave on an Application object generated by an ApplicationSet is **advisory only** — without an app-of-apps wrapper, ArgoCD syncs all generated Applications in parallel. ArgoCD's retry semantics handle ordering races (cert-manager → ALB webhook race resolves in 1-2 reconcile cycles). This matches the AWS Blueprints reference. See `docs/sync-waves.md` for full registry and the cross-Application ordering nuance.

## How to add a new chart (≤5 steps)

1. Create `charts/<name>/values.yaml` with chart values. Every Deployment **and Helm hook Job** that targets system-ng MUST include the `CriticalAddonsOnly:NoSchedule` toleration. Read the upstream chart's full `values.yaml` to find every toleration key (controllers, webhooks, jobs, cainjectors, …).
2. Create `bootstrap/applicationsets/<name>.yaml` copying the cert-manager template. Set `chart`, `targetRevision` (pinned, no `*` / `HEAD`), `destination.namespace`, `template.metadata.annotations.argocd.argoproj.io/sync-wave`, and explicit `releaseName`. Add `valuesObject` entries that reference `{{metadata.annotations.X}}` for any IRSA role / region / cluster-name needs.
3. Add `applicationsets/<name>.yaml` to `bootstrap/kustomization.yaml`'s `resources:`.
4. Open a PR. CI runs `kustomize build`, `kubeconform`, sanitization grep, and broader defense-in-depth grep. All must pass.
5. After merge, ArgoCD picks up the new ApplicationSet automatically (the controller will be self-managed at wave 0 once `argocd` chart lands in a later slice).

## Public-repo invariant (HARD)

This repo is **public**. **No file** contains a real AWS account ID, real role ARN, real OIDC URL, real VPC/subnet/SG ID, or real domain name. CI enforces this via two `grep` steps (mandatory issue-defined regex + defense-in-depth ERE patterns) — see `.github/workflows/validate.yaml`. Use `{{metadata.annotations.X}}` to inject account-specific data at ArgoCD sync time.

## Fork this template

The values-ref source's `repoURL` in `bootstrap/applicationsets/*.yaml` is hardcoded to `https://github.com/slikk66/eks-argo-bootstrap`. To fork:

```bash
# After forking, find/replace your fork's URL across all ApplicationSets:
git grep -l 'github.com/slikk66/eks-argo-bootstrap' | xargs sed -i '' 's|github.com/slikk66/eks-argo-bootstrap|github.com/<your-org>/<your-fork>|g'
```

The contract with `eks-pulumi` (14 annotations) is the sync surface — forks do NOT need to extend it for the repo URL.

## Local validation

`kustomize` and `kubeconform` must be installed locally (CI installs them on Ubuntu):

```bash
brew install kustomize kubeconform   # macOS
```

Run all three checks before opening a PR (CI runs the same):

```bash
kustomize build bootstrap/ > /tmp/rendered.yaml
kubeconform -strict -summary -ignore-missing-schemas \
  -schema-location default \
  -schema-location 'https://raw.githubusercontent.com/datreeio/CRDs-catalog/main/{{.Group}}/{{.ResourceKind}}_{{.ResourceAPIVersion}}.json' \
  -kubernetes-version 1.35.0 /tmp/rendered.yaml
grep -RIn 'arn:aws:iam::[0-9]\{12\}\|[0-9]\{12\}\.dkr\.ecr' . --exclude-dir=.git --exclude-dir=.dangeresque
```
